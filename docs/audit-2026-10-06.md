# Flux application audit — 6 October 2026

**Subsequent implementation:** [the fix record](audit-fixes-2026-10-06.md) documents corrections and regression results for A01–A19. A10 is mitigated but not fully resolved. The assessment below describes the audited commit.

Audited commit `94def42` on `main` (clean working tree at entry). This audit follows the two 4 October audits and their fix record. It re-verifies those fixes and concentrates on the seven commits since (`affc892..94def42`): 30-day logins, job reconnection, helper-exit handling, bundled Office fonts and the new **full-engine native Mac build**. It also covers areas the earlier audits did not exercise.

No application code was changed, committed, pushed, deployed, installed or submitted. The only repository changes are this report and `docs/audit-evidence/2026-10-06/`, both uncommitted.

## 1. Executive assessment

All existing automated checks pass, and the 4 October fixes still hold. The server's authorization, quota, scanning and isolation design remains careful.

The new defects concentrate in two places:

- **The new Mac build path.** It removed the distributable Mac build path. CI still passes because it builds an app with no converters.
- **The website's upload client.** It fails on slow connections, on older browsers, and whenever two other users are uploading at the same time.

The Electron desktop app also resolves **external references inside untrusted input files** against the local disk. In the strongest case, converting a stranger's 3D model to FBX silently embeds an arbitrary local file in the output.

**Most important next actions:**

1. Restore a buildable, functional restricted Mac target, and make CI exercise a conversion (A01).
2. Reject or neutralize external references in untrusted inputs (A02).
3. Make browser uploads resilient: smaller or adaptive chunks with a progress-based timeout, a feature fallback for `AbortSignal.any`, and per-user upload slots with client retry (A03–A05).
4. Fix publishing on exFAT and `%` handling (A06, A07).

**Limits of this assessment:**

- Production Cloudflare, Unraid, gVisor and ClamAV were not accessible. Docker is not installed here, so the container was not built or run.
- LibreOffice is not installed locally, so Office routes in Electron were not executed.
- The signed, installed Mac full-engine app was inspected (catalog and signing) but not driven through its UI.
- iPhone was not run on a device.
- No VoiceOver or Switch Control testing was done.

## 2. System and user-journey map

The surfaces, data flows and trust boundaries are unchanged from [the comprehensive audit §System map](audit-comprehensive-2026-10-04.md#system-and-user-journey-map), except for one addition.

**New since 4 October: full-engine Mac build.** `mac/Flux/SharedMacEngine.swift` replaces OfflineKit conversion in the native Mac app.

- The flow is: the WebKit UI talks to `DesktopBridge`, which stages inputs into `Caches/FluxLocalJobs/<uuid>`. It then spawns `ConversionEngine/bin/node --jitless scripts/mac-engine.cjs request.json`.
- That worker runs the same Electron/server adapters (`electron/engine.cjs`), with bundled Homebrew, Office and Calibre tools. It writes `reply.json`, and Swift validates the result path.
- The worker and every tool are signed `app-sandbox` + `inherit`.
- The engine is copied into the app only by `scripts/mac-release.py`, after Xcode archiving.
- Two builds of this kind are installed on the audit machine (`/Applications` and `~/Applications`). Their catalogs exclude 3D.

**iPhone** still uses OfflineKit and is unaffected by that change.

**Website changes:**

- Logins are accepted for 30 days (`server/auth.cjs:33`).
- The client now times out requests: 30 s generally, 120 s for each upload chunk (`server/web/app.js:25`).
- The client shows a "Connection lost / Reconnect" state and polls every 5 s while jobs are active (`app.js:670`).
- The supervisor now reaps short-lived helper processes and restarts only when a real service exits (`server/supervisor.c:95`).

## 4. Prioritized findings

### A01 — `main` cannot build a functional or distributable restricted Mac app, and CI passes anyway (High, confirmed)

- **Category:** release engineering / product completeness.
- **Affected:** any future native Mac release, including security updates to the restricted build previously prepared for TestFlight.
- **Expected:** `main` can still produce the restricted, distributable native Mac app. `docs/testflight.md` calls the full engine "separate from the previously uploaded restricted native release". CI's Mac build should be an app that converts.
- **Actual:** commit `0b31564` routed every native Mac conversion through `SharedMacEngine`, and no longer calls `OfflineEngine.convert` (`DesktopBridge.swift:145-147,170,210`).
  - The engine is not part of the Xcode project (no `ConversionEngine` reference in `project.pbxproj`). It is copied in only by `scripts/mac-release.py`.
  - That script now aborts without the full stage (`mac-release.py`, "Build the bundled converters…").
  - It also aborts any non-development build unless `distributionReady` is true and both architectures are bundled. Both conditions are blocked by unresolved licensing (see `docs/mac-full-engine.md`).
- **Reproduction:**
  1. Run `xcodebuild -project mac/Flux.xcodeproj -scheme Flux -configuration Release CODE_SIGNING_ALLOWED=NO build`, as CI does. The build succeeds.
  2. List `Contents/Resources`. It contains `DesktopUI`, `OfflineKit_OfflineKit.bundle` and others, but **no `ConversionEngine`**.
  3. In that app, `SharedMacEngine.families` is `[]` (`SharedMacEngine.swift:15`), so no formats are offered. `convert` throws "bundled conversion tools are missing" (`:21`).
- **Evidence:** `docs/audit-evidence/2026-10-06/suite-results.txt` (CI-equivalent build section).
- **Root cause:** the full engine replaced the restricted engine instead of being added as a separate target. The CI job checks compilation, not function.
- **Impact:** the distributable Mac app cannot be updated from `main` until licensing is resolved or the change is reverted. CI gives false assurance. Existing installed builds are unaffected.
  - Rated High as a release blocker with misleading CI status. No direct user-data harm.
- **Correction:** make the full engine a separate scheme or build flag (for example, the `fullEngine` state already in `DesktopBridge`), with OfflineKit as the default restricted path. Give each variant its own catalog, limits and support text. Add a CI step that launches the restricted app or bridge and converts a sample.
- **Verification:** the CI-built restricted app lists formats and converts the bundled PNG sample. `mac-release.py` produces a restricted distribution build without a full stage. The full build is still gated on `distributionReady`.

### A02 — External references in untrusted input files are resolved against the local disk (Medium, confirmed)

- **Category:** security / privacy.
- **Affected:**
  - The Electron app, with locally installed Blender, Calibre, ImageMagick and FFmpeg.
  - The Mac full engine shares these adapters but excludes Blender in the installed builds.
  - The server worker includes Blender. Its readable file set is small (gVisor, per-job scratch, separate UIDs), and that path was not tested in a container.
- **Expected:** an output contains only data derived from the selected file, or the conversion rejects it.
- **Actual:**
  - **3D (independently reproduced):** a `.blend` whose image node points at `//../private/notes.txt` (relative to the model, so the attacker needs no username) converts successfully to **FBX containing that file's bytes**. The model itself does not contain the canary.
    - The OBJ route writes the victim's absolute path, including the home folder name, into the shared `.mtl`. GLB did not leak.
    - The reviewer reproduced the same leak for USDZ output, and for OBJ+MTL input to FBX.
  - **Calibre:** HTML → MOBI/AZW3 includes linked local HTML from outside the document folder (reviewer-confirmed; `--max-levels 0` removed it).
  - **ImageMagick MSVG:** `<image>` pulls in local images. The desktop uses Homebrew's open `policy.xml`; only the container ships `deploy/imagemagick-policy.xml`.
  - **FFmpeg:** `.m3u8` is accepted as video, and its segments can reference other local media files.
- **Reproduction:** `docs/audit-evidence/2026-10-06/probes/blend-make.py`, `blend-run.cjs`, `electron-repro-results.txt`.
- **Evidence:**
  - `resources/models.py:17,21` (`pack_all`; FBX `path_mode='COPY', embed_textures=True`)
  - `electron/engine.cjs:614-616` (Calibre called with default link depth)
  - `engine.cjs:130-134` (format filter omits `msvg`)
  - `electron/process.cjs` (`file` protocol is allowed)
- **Root cause:** every adapter trusts the input's external resource paths. Execution protections (`--disable-autoexec`, `use_scripts=False`, Pandoc `--sandbox`, Ghostscript `-dSAFER`, network protocol whitelist) are in place, but file-reference containment is missing.
- **Impact and conditions:** the user converts a file from someone else and then shares the output. A readable private file (keys, documents) travels with it, silently.
  - Medium: it requires attacker-supplied input, a particular output format, and sharing the result. The impact is confidentiality loss with no visible sign.
- **Correction:**
  - **Blender:** after import, enumerate `bpy.data.images/fonts/sounds/movieclips/volumes/cache_files/libraries`. Reject any unpacked external path or linked library, or clear them, before `pack_all` or export.
  - **Calibre:** pass `--max-levels 0` for HTML input.
  - **ImageMagick:** ship a desktop `policy.xml` through `MAGICK_CONFIGURE_PATH` that denies MSVG/MVG/MSL/TEXT/URL and `@` reads.
  - **FFmpeg:** reject probed `hls`/`concat` formats.
  - **Generally:** stage each input alone in a private folder before invoking tools.
- **Verification:** the supplied canaries reject or produce outputs without the canary. Ordinary packed-texture models, HTML and SVG still convert.

### A03 — Website uploads fail on uplinks below about 1.1 Mbit/s (Medium, confirmed)

- **Affected:** website users on constrained links (rural DSL, congested mobile, tethering) uploading files larger than 16 MiB. That includes the advertised 5 GB media workflow.
- **Expected:** a slow connection makes uploads slow, not impossible.
- **Actual:** every 16 MiB chunk must finish within a fixed 120 s (`server/web/app.js:25`, `security.cjs:6`).
  - At 100 KiB/s, a 20 MiB upload failed at 121 s. The server had received 12.3 MB of the first chunk, and the upload was discarded.
  - At 200 KiB/s the same upload succeeded (104 s).
  - The message ("Check the connection and reconnect") implies a retry will help. It will not.
- **Reproduction:** `probes/slow-upload.cjs` (Chromium upload throttling via CDP against the real API, with a stub scanner and worker). Results are in `slow-upload.txt`.
- **Root cause:** commit `90d5ca3` added a whole-request timeout sized for fast links, on top of a large fixed chunk.
- **Correction:** time out on lack of progress rather than total duration (for example, stream the chunk with an upload-progress watchdog), or make the chunk size adaptive (for example, 2–4 MiB). Retry a failed chunk from the server's confirmed offset instead of discarding the upload. Keep the server's offset and size checks.
- **Verification:** the same probe at 50 and 100 KiB/s completes. Outage and cancellation tests still pass.

### A04 — Website uploads break on browsers without `AbortSignal.any` (Medium, confirmed by emulation)

- **Affected:** Safari before 17.4 (including iPhones that cannot update past iOS 16 or 17.0–17.3), Chrome before 116, Firefox before 124.
- **Actual:** every request that carries a cancel signal, including every upload chunk, calls `AbortSignal.any` (`app.js:25-27`).
  - With that one API removed, the page loads, but every upload fails immediately with "AbortSignal.any is not a function".
  - The unmodified control succeeded.
- **Reproduction:** `probes/abortany.cjs`, `abortany.txt`. Real old Safari was not run; feature support is per MDN browser-compat data.
- **Correction:** use a small fallback that links two controllers manually when `AbortSignal.any` is missing. State a supported-browser baseline in the README.
- **Verification:** the emulation probe uploads successfully. Optionally run the existing web suite under Playwright WebKit.

### A05 — Server-wide limit of two concurrent chunk uploads rejects other users (Medium, confirmed)

- **Actual:** `uploading >= 2` is global across all sessions (`server/app.cjs:61,288`).
  - While two other users each have a chunk in flight, an unrelated third user's chunk gets `429 Too many simultaneous uploads.`, with no `Retry-After`.
  - The browser does not retry PUTs (they bypass `quotaRequest`). It shows the error and deletes the upload. `/api/status` afterwards shows 0 files.
  - Combined with A03, a slow uploader can hold a slot for up to 120 s per chunk.
- **Reproduction:** `probes/concurrent-upload.cjs` (API level) and `concurrent-browser.cjs` (end to end).
- **Root cause:** a capacity guard (sensible for disk I/O) without fairness or client back-off.
- **Correction:** make slots per session, with a higher or queued global cap. Return `Retry-After`, and have the client wait and resume the same offset rather than discarding.
- **Verification:** three or more concurrent synthetic users all finish. The flood and quota tests still pass.

### A06 — Electron output on exFAT/FAT always fails (Medium, confirmed)

- **Actual:** `publish()` only uses `fs.link` and only handles `EEXIST` (`electron/engine.cjs:828-840`). The same applies to compress and pack.
  - On an exFAT volume, every conversion fails with the raw text "ENOTSUP: operation not supported on socket, link …". The stage is cleaned up, so nothing is left behind.
  - exFAT is the default format for most USB drives and SD cards.
- **Reproduction:** `probes/exfat-run.cjs` with a disposable 20 MB `hdiutil` ExFAT image.
- **Correction:** on `ENOTSUP`/`EPERM`/`EXDEV`, fall back to `fs.copyFile(src, dest, COPYFILE_EXCL)` within the same unique-name loop. That keeps the no-overwrite guarantee.
- **Verification:** the probe succeeds. Existing no-overwrite and unique-name tests pass.

### A07 — `%` in names converts the wrong file or breaks conversions (Medium, confirmed)

- **Actual:** ImageMagick and FFmpeg expand printf-style patterns in paths, and Ghostscript expands them in `-sOutputFile`.
  - With red `scan%03d.jpg` and lime `scan000.jpg` in the same folder, converting `scan%03d.jpg` → JXL **reports success and outputs the lime image**. PNG and WebP, which use a different path, are correct.
  - The reviewer showed that output folders such as `Q3%done` or `100% Complete` break the ImageMagick, "Smaller PDF" and video→still routes.
- **Evidence:**
  - `engine.cjs:354,384` (`input + '[0]'`) and `inspectFile`
  - `compression.cjs:193` (`-sOutputFile=${out}`)
  - `engine.cjs:372,457ff` (FFmpeg still-image output)
  - Reproduction: `probes/percent-run.cjs`
- **Impact:** a successful, plausible but wrong result. That combination is rare, but it is the silent-corruption class. Folder failures are more common, and visible.
- **Correction:** run tools with `cwd` set to the stage directory and fixed safe relative names (copy or link the input to `input.<ext>`). Escape `%` as `%%` for Ghostscript, and use `-update 1` for FFmpeg single-image output.
- **Verification:** the probe produces red for every target. Folders with `%` succeed.

### A08 — Mac full engine: "Archive → ZIP" wraps instead of repacking (Medium, confirmed by code and installed catalog)

- **Actual:**
  - `SharedMacEngine.targets` always appends `zip` (`SharedMacEngine.swift:19`). The catalog already lists `zip` for 7z, tar, rar, gz and others, so ZIP appears twice.
  - `mac-engine.cjs:82-91` routes every `zip` target to `compress(..., 'archive')`, which zips the original file.
  - The UI note, taken from the installed catalog, says "Repacks archive contents. Symlinks and unsafe paths are rejected." Electron (`main.cjs:461-477`) does repack.
  - `pathExtension` treats `x.tar.gz` as `gz`, then offers TGZ, which the worker rejects.
- **Correction:** wrap only when the format's own targets lack `zip`; otherwise call `convert()`. Deduplicate targets and recognize multi-part extensions.
- **Verification:** 7z/tar/rar → ZIP contains the members, not the original archive. Each target appears once.

### A09 — Mac full engine: quitting or crashing leaves conversions running (Medium, strongly supported)

- **Actual:**
  - There is no terminate hook (`FluxApp.swift`, `DesktopBridge`).
  - Cancellation sends SIGTERM to Node, which forwards it to tool groups (this path works). After 4 s, the SIGKILL fallback kills only Node (`SharedMacEngine.swift:63-70`).
  - Tools run in their own process groups (`process.cjs:76,90`), and the worker has no parent-death detection.
  - The reviewer's probe showed a Foundation `Process` child outliving its parent (reparented to launchd).
  - Result: LibreOffice or FFmpeg can keep running for up to 10 minutes after Quit, writing into `Caches/FluxLocalJobs`. This contradicts the privacy text's cleanup description.
- **Not executed:** quitting the installed app mid-conversion.
- **Correction:** pass Node a stdin pipe and abort on EOF (this also covers a crash). Add an `applicationWillTerminate` cancel. Have the SIGKILL fallback also target recorded tool process-group IDs.
- **Verification:** start a long FFmpeg job, then quit or `kill -9` the app. `pgrep -f ConversionEngine` is empty within about 3 s.

### A10 — Mac full engine: converters inherit network and user-file access (Medium, strongly supported)

- **Actual:**
  - Tools are signed `app-sandbox` + `inherit` (`scripts/mac-sign-engines.py:10,14`), so they inherit `network.client` (`Flux.entitlements`, present for WebKit).
  - They also inherit the security scopes the bridge keeps open: up to 100 selected originals and the output folder (`DesktopBridge.swift:97,164-165`).
  - The bundled ImageMagick policy is the permissive default, and the LibreOffice profile only disables macros.
  - `docs/mac-full-engine.md` says children "receive only private staged file copies". That is true of their arguments, not of what they can access.
- **Scenarios:**
  - A DOCX with a remote linked image could make LibreOffice fetch the URL, beaconing the user's IP. This contradicts "no uploads / entirely on the device". **Not verified:** no listener test was run in the signed app.
  - A parser exploit could read or modify other selected originals.
- **Correction:** run the worker in an XPC service, or as a helper with its own sandbox: no `network.client`, no user-selected entitlement, inputs passed as staged copies. Ship restrictive ImageMagick and LibreOffice (link/remote-graphics) settings.
- **Verification:** a linked-image DOCX in the signed app triggers no request on a local listener. A worker probe cannot open an unstaged original.

### Lower-severity findings

**A11 — Mac full-engine deadline vs advertised 5 GB media** (Low, strongly supported)

- The 600 s deadline starts before staging (`LocalPolicy.swift:18-23`).
- Encoding uses 2-thread software x264/VP9. The reviewer measured about 121 fps (x264) and about 40 fps (VP9) at synthetic 1080p, so files of about 40 minutes or more cannot re-encode within the limit.
- Fix: use VideoToolbox, more threads, or a duration-scaled deadline, or lower the stated limit.
- Related website wording: during an outage, the banner says "Try reloading shortly" while the status line says it is retrying automatically (`probes/reconnect-mobile.png`). The layout is fine at 390 px.

**A12 — Output naming** (Low, confirmed)

- `path.basename(name, '.' + lowercaseExt)` turns `Photo.JPG` into `Photo.JPG.png` (`engine.cjs:863`, `compression.cjs:102`, `archives.cjs:65`).
- `outputStem` replaces combining marks, so NFD `café` becomes `cafe_` and Devanagari is damaged.
- Fix: strip extensions case-insensitively, normalize to NFC, and allow `\p{M}`.

**A13 — Electron persistence edges** (Low, strongly supported)

- A `save()` failure after `publish()` marks the job as an error even though the output exists, so a retry creates "(1)" duplicates (`main.cjs:481-489`).
- `.flux-*` stage directories in the output folder are not swept after a crash; they can be synced by iCloud or Dropbox.
- `persist()` renames without fsync.

**A14 — Full-engine error text** (Low, confirmed in source)

- The last 4 KB of `worker.log` becomes the user-facing error (`SharedMacEngine.swift:72-75`).
- A signal or early crash gives an empty message; a module-load failure shows a Node stack trace with container paths.

**A15 — Stale documentation for the full Mac build** (Low, confirmed)

- The in-app and public support text says 512 MB for other files and "Flux does not launch separate command-line conversion workers". The app enforces 1.9 GB and spawns a worker.
- The full-engine description in `src/main.jsx` lists 3D, which is excluded.
- `docs/mac-full-engine.md` overstates child isolation (A10).

**A16 — Operations** (Low, strongly supported; Docker semantics not executed)

- Any service exit stops the whole container by design. `--restart=on-failure:3` is a lifetime count in Docker, so the fourth failure leaves Flux down until someone starts it manually, and nothing alerts. The health check does not cause a restart.
- Images are cosign-signed in CI, but `start-unraid.sh` and the Unraid Update button pull `:stable` without verifying the signature.
- gVisor is downloaded from `latest`, with the checksum fetched from the same origin.
- `cloudflare/cloudflared:latest` and the Node/Debian base images are mutable tags.
- Fix: add an external uptime alert, and either reset or raise the restart budget or monitor it. Verify image signatures or pin digests, and pin gVisor.

**A17 — Full-engine build provenance** (Low)

- `scripts/mac-engines.py:28` bundles `bin/node` from a local agent-tool cache, with no pinned version or checksum.
- The `architectures` field is derived from Node alone, so the release gate could pass with arm64-only tools.

**A18 — Native accessibility** (Low, strongly supported; VoiceOver not run)

- An unlabeled `Slider` (`native/App/LocalView.swift:74`).
- A decorative icon that VoiceOver still reads (`:26`).
- Status and error changes are not announced (`:80,95`).
- The Mac minimum window of 1000×720 exceeds a 13-inch "Larger Text" display (1024×640) (`mac/Flux/FluxApp.swift:9`).

**A19 — CI coverage gap** (Low, confirmed)

- CI runs 4 of 7 Node test files, plus one test name pattern.
- It omits `conversion.test.cjs` (13 tests), `extended.test.cjs` (9) and 2 of 3 `audit-fixes` tests.
- It also omits the Electron desktop suite and `tests/mac-bundled-engine.cjs`.
- The container smoke test covers some real conversions, but A06/A07-class regressions in Electron would not be caught.

### Product decisions (not defects)

- **30-day login:** API tokens are accepted for 30 days (`auth.cjs:33`), as documented. A stolen owner cookie stays valid for that long. Cloudflare's edge revocation is the primary control. The owner is identified by email, so the identity provider's email claim must be trustworthy.
- **Full-engine licensing (AGPL/GPL components):** correctly flagged and gated in `docs/mac-full-engine.md`. This needs specialist review before any distribution.
- **Capacity:** global storage is 12 GB with a 5 GB reservation per job. One user's large job can block other users' large uploads. This is acceptable for a private service but should be documented.

## 6. Remediation roadmap

**Immediate (release blockers and silent-harm fixes):**

1. **A01:** separate restricted and full Mac targets, and add a functional CI conversion check.
2. **A02:** external-reference containment for Blender, Calibre, ImageMagick and FFmpeg playlists; ship a desktop ImageMagick policy.
3. **A07:** stage inputs under safe names; escape Ghostscript output paths.
4. **A04:** `AbortSignal.any` fallback. Small and low risk; ship with the next web image.

**Near term (website reliability, then desktop compatibility):**

5. **A03 + A05 together:** progress-based timeouts or smaller chunks, offset-resume retries, per-session slots with `Retry-After`. Change the client and API together and test before promoting `:stable`.
6. **A06:** copy fallback in `publish()`.
7. **A08, A09, A14:** full-engine routing, lifecycle and error handling. Fix before relying on the installed personal build for large jobs.
8. **A12, A13, A15:** naming, persistence and docs.

**Longer term:**

9. **A10:** XPC or separately sandboxed converter service; resolve licensing before any distribution.
10. **A16, A17:** alerting, signature or digest pinning, reproducible Node runtime.
11. **A11:** hardware encoding or deadline scaling.
12. **A18:** VoiceOver pass.
13. **A19:** move the real-format and Electron suites into CI on macOS runners with pinned engines.

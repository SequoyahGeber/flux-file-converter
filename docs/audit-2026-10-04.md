# Flux stability, safety and performance audit

Audited on 4 October 2026 in the File converter workspace. The audit produced fixes across the native Mac/iPhone engine, desktop bridge, Electron converter, browser client, server lifecycle and archive helpers. All changes are local source changes; this audit does not establish production deployment, App Store approval or physical-device acceptance.

The strongest measured improvement is large-file staging: peak resident memory for a synthetic 512 MiB copy fell from **520.9 MiB to 9.9 MiB** after adding a per-chunk autorelease pool. The copy remains cancellable and rejects links, replacement of existing destinations, and changes to the source length.

## Scope

Reviewed the conversion paths for images/PDF, documents, structured data, subtitles, audio/video, archive creation/extraction and compression; file selection and export; security-scoped access; job state, cancellation, deadlines and scratch cleanup; authentication, invitation/owner controls, request validation, quotas and queue isolation; Electron IPC/WebKit boundaries; helper processes and deployment restrictions; packaging/signing checks, support limits and dependency reports.

Validation used synthetic files and isolated scratch directories. Existing baseline suites were run before changes, then the affected suites and UI workflows were repeated. Coverage includes corrupt/encrypted archives, unsafe paths, malformed documents, oversized expansions, data integrity, cancellation races, streamed request races, empty files and repeated conversions. It is not an exhaustive corpus of every codec, file provider or malformed input.

## Repairs

| Area | Defect and resulting behavior |
| --- | --- |
| Large-file staging | Foundation read buffers accumulated on background threads. A pool per chunk keeps the tested 512 MiB copy near 10 MiB resident memory; ZIP provider/consumer buffers now also have bounded lifetimes. |
| Native file safety | Copying could follow links or overwrite a destination. Inputs now open with `O_NOFOLLOW`, are checked with `fstat`, and outputs use exclusive creation. Growth/shrinkage is rejected. |
| ZIP integrity | ZIPFoundation iteration can stop at an encrypted or unreadable entry and expose a partial archive. Native extraction now preflights the entire central directory, including ZIP64 metadata, and verifies the iterated count. Encryption, unsupported methods, special files and inconsistent metadata reject the whole job. |
| ZIP resource limits | Python folder packing eagerly materialized the tree and trusted prior file sizes. Packing now traverses lazily, opens regular files without following links, and enforces actual streamed bytes. ZIP compression uses this same bounded helper. |
| Archive output | Long multibyte output stems could exceed filesystem limits; Linux compatibility packing lost empty directories. Stems now have a UTF-8 byte budget, and empty directories survive packing. |
| Native job setup | Invalid options or directory setup failures could leave job folders. Names/quality are validated before setup, all setup is covered by cleanup, and staging uses `.inputs` so extraction named `inputs` succeeds. |
| Export | Folder exports lacked the file export's atomic staging. Folder exports now stage on the destination volume and refuse an existing destination; explicitly confirmed file replacement keeps atomic staging. |
| Cancellation | A late native result or worker inspection could publish after cancellation. Late results are removed and cancelled uploads do not enter the file list. AVFoundation export is allowed to stop before its working directory is removed. |
| Desktop selection/state | Selection, inspection, conversion and release could overlap. Guards now serialize incompatible actions, reject excessive selections before discarding the previous result, and catch asynchronous open/startup errors. Native history is capped at 100 results and evicted scratch outputs are removed. |
| Interface failure | Native WebKit protection compilation could leave a blank window without an explanation. Startup now reports the failure and exits while preserving the network blocker. |
| CSV integrity | Duplicate/empty headers could silently discard values. Native and Electron table conversion reject them. The native parser enforces limits on the final row as well as newline-terminated rows. |
| CSV meaning/safety | Native booleans could become 1/0. They now remain true/false. Formula-like text and headers receive an apostrophe prefix; numeric negatives remain numeric. Table shape and incremental output byte limits are enforced. |
| Structured-data bounds | Electron reads trusted stale size metadata and accepted replacement-decoded UTF-8. Reads now enforce actual bytes and strict UTF-8; value/depth/table limits prevent avoidable expansion. Null option objects are normalized safely. |
| Document memory | Repeated compressed DOCX image references could consume excessive decoded memory. Dimensions and an aggregate 128 MiB estimated decoded budget are checked before decoding. |
| PDF output | Scanned PDFs could report successful empty text output. They now explain that selectable text/OCR is required. PDF helper page, text and render-dimension bounds are checked before allocation or integer conversion; multi-page compression releases temporary page buffers. |
| Audio/video correctness | ALAC/FLAC decoding used Float32 for integer samples, risking precision loss; integer audio now uses Int32. Electron video scaling now produces even dimensions required by H.264. |
| Server parsing/concurrency | Fragmented Japanese UTF-8 JSON was decoded chunk by chunk. Requests now decode once, reject invalid UTF-8/non-object JSON, and recheck job capacity after awaited body reads. |
| Server cleanup/shutdown | Expiry could remove a session during body preparation; shutdown could remove scratch before background scanning stopped. Request lifetimes/removal state are tracked, cleanup failures remain retryable, and shutdown awaits tracked work after cancellation. |
| Browser upload control | Upload/scanning cancellation was incomplete, abandoned uploads retained reservations, and missing jobs could poll forever. The client aborts uploads, releases pending uploads through an owner-scoped endpoint, handles late submission cancellation and reports missing jobs. Progress and Cancel remain visible even before the first file finishes inspection. |
| Worker protocol | Zero-byte trailing files failed transport, and an already-cancelled job could spawn a process. Transport now writes all empty inputs and execution checks cancellation before spawning. |
| History feedback | Native Clear history removed temporary results while queue rows still offered them. Rows now return to ready and the message explains that saved files remain. |

The offline support text and source support page describe the table, decoded-image and scanned-PDF limits. The public page source was updated locally; publishing was not part of this audit.

## Remaining verification boundaries

- Physical iPhone memory, thermal behavior, background interruption, low-storage conditions, and third-party Files providers were not exercised. Simulator success does not establish those results.
- Docker is unavailable on this Mac. Linux converter engines, live ClamAV, gVisor/seccomp enforcement, restart recovery and production deployment were reviewed statically and through mocked server/protocol tests; an actual container smoke run remains necessary on the deployment host.
- Intel Mac code was compiled, not executed on Intel hardware.
- Native deadlines are cooperative; some synchronous Apple framework operations cannot be interrupted immediately. Storage/output checks also do not replace device-level failure testing.
- npm's advisory scan covers reported JavaScript advisories. It is not a vulnerability guarantee for Apple frameworks, bundled native media libraries or external desktop/Linux tools.
- No installed user app was replaced, and no changes were pushed, deployed or submitted to Apple. Release signing, processing, installation and approval remain separate checks.


## Follow-up: initial Cloudflare login return

The reported Safari screenshot showed `{"error":"Cross-site requests are blocked."}` on the first return from login, with a refresh succeeding. The blanket Fetch Metadata check in `server/auth.cjs` also rejected the authenticated landing-page navigation. Browsers retain cross-site classification across a cross-site redirect chain ([Fetch Metadata specification](https://www.w3.org/TR/fetch-metadata/#redirects)).

The guard now accepts only an authenticated top-level GET of `/` (including query parameters) with `Sec-Fetch-Mode: navigate` and `Sec-Fetch-Dest: document`. Token signature/issuer/audience/expiry and host checks still run first. Cross-site API requests, scripts, iframes and writes remain blocked; exact Origin/custom-header write checks are retained.

The new browser regression uses two local sites, an actual HTTP redirect and a signed synthetic Access assertion with the production authenticator. Against the previous authenticator it reproduces the exact reported error and captures `cross-site`, `navigate`, `document` metadata. Against the fixed authenticator, three returns load the authenticated workspace without refreshing. It runs in Chromium, with no live Cloudflare login or Safari/device claim. `npm run test:web` now includes this regression. All 53 JavaScript tests and all three browser acceptance suites passed; source formatting and diff checks passed. [Before](audit-evidence/2026-10-04/login-before.txt), [auth checks](audit-evidence/2026-10-04/login-security-tests.txt), [browser result](audit-evidence/2026-10-04/login-browser.txt).

The fix is local source work. A newly published container image and an Unraid update are required before this behavior changes on the live website; neither was performed in this follow-up.
